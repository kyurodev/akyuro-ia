Créer un relecteur de code en fichier Markdown

Guide du reel « Un relecteur de code en fichier Markdown » · mis à jour le 25/11/2026

Maintenant, Claude peut te créer un sous-agent relecteur : un simple fichier Markdown qui relit ton code dans sa propre fenêtre et ne te renvoie que le résumé. Ta conversation principale reste lisible.

Ce qu'il te faut

  • Un projet de code sur lequel tu travailles avec Claude, dans l'environnement décrit par la documentation en source (code.claude.com).
  • Un accès qui permet d'utiliser les sous-agents. La fiche ne précise pas les offres concernées : vérifie selon ton offre.
  • Une idée claire de ce que ton relecteur doit regarder (lisibilité, bugs, conventions de ton client…).

Étapes

  1. Demande à Claude d'écrire le sous-agent pour toi. Pas besoin de partir de zéro : décris-lui le rôle voulu, par exemple « Crée-moi un sous-agent relecteur de code qui vérifie mes modifications et me renvoie un résumé court ».
  2. Regarde le fichier qu'il produit. Un sous-agent est un fichier Markdown avec un en-tête YAML. Dans cet en-tête, seuls les champs « name » et « description » sont obligatoires. D'autres champs comme « tools » ou « model » peuvent apparaître si Claude les juge utiles.
  3. Vérifie où le fichier est rangé. Tu le verras en général dans un dossier « .claude/agents/ » ou « ~/.claude/agents/ ». Garde l'emplacement que Claude te propose, sauf si tu sais pourquoi en changer.
  4. Ajuste les consignes si besoin. Le corps du fichier sert de prompt système personnalisé à ton relecteur. Précise ce qu'il doit relever et la forme du résumé que tu veux recevoir.
  5. Fais-lui relire ton code. Il n'y a pas de syntaxe spéciale : nomme simplement le sous-agent dans ta demande, par exemple « Demande au relecteur de vérifier ce fichier », et Claude lui délègue en général la tâche. Tu peux aussi le désigner directement avec « @"code-reviewer (agent)" » si cette option t'est proposée.
  6. Lis le résumé. Le sous-agent fait le travail dans son propre contexte et ne renvoie que le résumé. Ta conversation principale ne se remplit pas de tout le détail de la relecture.

Bon à savoir

  • Chaque sous-agent tourne dans sa propre fenêtre de contexte, avec son propre prompt système, des accès aux outils précis et des permissions indépendantes. Pratique quand tu jongles entre plusieurs projets clients.
  • Un sous-agent envoie ses propres requêtes. Elles comptent dans les mêmes limites d'utilisation que ta conversation principale : garde-le pour les relectures qui en valent la peine.
  • La délégation par le nom marche « en général ». Si Claude ne passe pas la main, reformule en nommant clairement le sous-agent.
  • Comme c'est un simple fichier, tu peux le relire, le corriger ou le supprimer quand tu veux.
